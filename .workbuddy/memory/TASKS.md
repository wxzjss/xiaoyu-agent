### 8. 回复1 排到消息2 后面（逐帧：消息1/消息2 → 一秒后恢复四条）
- **根因**：`_pendingLanded` 判据「历史最后一条 assistant 下标 > 最后一条 user 下标」

  那条「最后一条 user」永远是上一轮。于是刚发消息就裁掉上一轮回复，回复1 只能从 live 补回来，
  而 `items.concat(pend, live)` 把 live 排在 pend 之后 → 站到消息2 后面。
- **修法**：判据改成「**这一条 pending 自己**落盘并答完了没有」。
- **证据**：真页 60ms 连拍 15 秒，全程无错序帧；`check-live-items-parity` 40 过 / 0 挂。

## 三、已知的坑（踩过，别再踩）

1. **`public/index.html` 是 CRLF** —— 从源码切函数体前必须 `.replace(/\r\n/g,'\n')`，
   否则 `indexOf('\n}\n')` 返回 -1，断言全变假红（今天两个脚本栽在这上面）。
2. **Electron 跑的是 `data/public/` 副本** —— 改仓库的 `public/` 必须 `sync-live`，
   否则主人看到的永远是旧界面（stream-perf 因此误测了一轮 DOM 间隔）。
3. **改了 `src/` 必须重启进程** —— 关窗口不算。
4. **`SCREEN_OFF_SCRIPT` 是模块加载时的常量** —— 进程启动那一刻算一次，之后不重算。
5. **修一个放宽的条件会造出新 bug** —— 上午修闪屏时放宽 `trimTurnsForLive`，
   下午就出了「两个小鲸」。收紧/放宽都要想清楚副作用。
6. **`readAll()` 加缓存必须读写分家** —— 22 处原地修改，中途 return 会污染缓存
   （表现为「新建的卡重启就消失」）。
