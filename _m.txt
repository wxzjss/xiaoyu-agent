fix: 静默阈值 90→300 秒 / 事件补 at / 输入法整块撤掉

三件事，主人一句一条：

① 「【已经x秒没有回音】为什么正常运行一直计数，而且是从当前轮总用时来的」
   —— 真凶在 /api/running 算 idleMs 的方式：它往前找「最近一个带 at 的事件」，
   找不到就退回 startedAt。而主路径 send0 里 push 事件时**没带 at**，
   于是一条都找不到，idleMs 恒等于「这一轮跑了多久」，90 秒一到就误报。
   （同一个坑 11-07 在小鲸那条上踩过，当时只补了注释，主路径漏了。）
   现在补 at：idleMs 才是真正的「距上一次有动静」。

② 「把【已经x秒没有回音】阈值改为 300 秒」
   RUNNING_STALL_MS 90000 → 300000，跟后端「等模型上限 300 秒就掐」对齐：
   90 秒时模型长思考本来就不吐字，正常也被判卡住；300 秒才是真该报、
   而且同一时刻后端也要动手。提示文案和列表绿点变黄共用这个常量，一起变。

③ 「把有关输入法的改动全删了，重做成和 workbuddy 一模一样的」
   查清了：WorkBuddy **什么都不做** —— 它压根不碰系统输入法。
   切过去是中文，只因为 Windows 按窗口各自记 IME 状态。
   我们这一路从 10-27 折腾到现在（临时美式键盘 → imm32 翻位 → 开机先切好 →
   koffi 直连），每一版都在「主动掰」，每一版都换来新毛病。方向就错了。
   现在：
   · electron/main.cjs 里 koffi 那段 + 窗口 focus 挂载整段撤掉（换成说明）
   · 前端 input 的 focus / pointerdown 不再调 imeMatchSoon（两处停用）
   · imm32 脚本和 ime:matchSystem 这个 IPC 保留（功能面板的手动开关还要用），
     但不再在任何时机自动调用
   输入法完全交给 Windows 和主人自己（Shift / Ctrl+Space）。

验证：预检通过、页面脚本语法通过、已同步。
