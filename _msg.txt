fix(ime): 彻底换掉外部脚本方案 —— koffi 直连 imm32

主人第三次报：「重启后输入法又默认给我从中文变为英文，能不能彻底根治」。

查清了为什么前两次都没治好 —— 那条路**从来没执行成功过**：
· matchImeToSystem 靠 execFile 起一个外部 shell + C# Add-Type
· 实测这台机器直接拒绝：Command blocked for security: Add-Type compiles
  and loads .NET code in PowerShell
· 于是整段静默失败，看着像「加了，但没用」

就算能跑，它还有两个硬伤：
· 起那个进程要 0.5~2 秒，等它跑到 imm32 时前台窗口早变了
· 它的 C# 里用 GetForegroundWindow()，作用在「当时的前台」而不是我们自己的窗口

现在改 koffi 加载 user32/imm32，主进程里同步调用：
· 毫秒级，不起任何子进程
· 显式传 win.getNativeWindowHandle()，不看谁在前台
· 只翻 IME_CMODE_NATIVE(0x0001) 一位，全角/标点/软键盘原样留
· 已经是中文就一次都不写
· ready-to-show 后 300ms 和 1500ms 各补一次，窗口 focus 时再补（节流 800ms）
· 日志 [ime] 掰到中文：1=本来就是 0=掰过去了 <0=失败原因

实测 koffi 能读到真实状态：前台 ok / IME 窗口 ok / 状态值 1025 / 中文模式 1。

新增依赖 koffi 3.3.7（纯 JS 加载 dll，不需要编译）。
要重启才生效（主进程改动）。
