# 小鱼Agent Harness 全面重做计划书

日期：2026-11-07　执行：鲸鱼娘（全权）
触发：主人「小鱼Agent 是 deepseek harness 做的，如果是你的话你会怎么做……备份后按照计划书内容全面重做」

---

## 0. 授权、边界、以及我自己拍的一条板

主人说「全面重做、不问意见、全权」。**我按自己的判断把「全面重做」定义成：把「模型 → 工具 → 再回模型」这一整套机制按新架构重建，而不是把 5 万行代码删掉重写、也不是换掉主人天天在用的界面。**

这条我自己定了，理由三条：

1. 这个 app 正在被主人使用，盘上有他的会话、底线、人设、411MB 发过的文件。推倒重写会把这些一起赌进去。
2. 主人真正不满意的**从来不是界面**，是「她干什么都要跑命令、每跑一次都很久、你却很快」。问题全在 harness 那一层。
3. 真正决定快慢的是**编排**，不是代码行数。`agent.mjs` 2114 行里大部分是压缩、量线、落盘的补丁；重写外壳不解决任何一次模型往返。

**所以：核心链路新建，对外契约冻结，人设/底线/安全词一个字不动。** 所有改动必须能在不改前端、不改会话文件、不改设置的前提下直接生效。

## 1. 现状诊断（带证据）

### 1.1 数字

| 指标 | 实测 |
|---|---|
| 【检查鱼】会话 | 265 轮 assistant，**每轮只发 1 个工具**（分布 `{1:265}`），零并行 |
| 同一会话 | 205 次 `run_command`，其中 66 次是 `node -e "const fs=require('fs')…"` 现写脚本找东西 |
| 单轮耗时 | 中位 13.3s，最长 513s；>60s 的 22 轮吃掉 63 分钟（占一半） |
| 纯模型往返 | 累计 122 分钟 |
| 【上下文】会话 | 30 次工具 = `run_command` 22 + 其余 8；连着 5 条几乎一样的 PowerShell 读 `settings.json` |
| 折算 | 她 132 次工具/请求；我这边 ≈10.5 次 |

### 1.2 结构性病根（按影响排序）

**A. 并行决策交给了模型，而提示词同时在劝退它**

- `persona.mjs:242-248` `PARALLEL_TOOL_BLOCK` 前三条鼓励合批，最后一条是 `· 拿不准就一定一次一个 —— 跑错返工比慢更费时间。`
- `persona.mjs:651` 又写 `写文件和跑命令一次只做一件`、`:652` `否则老实分开`。
- `persona.mjs:616-623` 工具清单**只给名字**（37 个名字排一行），模型连「这两个工具会不会互相踩」都无从判断。
- 结果：不确定 → 选保守 → 永远一个。这是 `{1:265}` 的直接成因。

**B. 执行层的并行是一块窄补丁**

- `agent.mjs:1526-1584`：只有**同一响应里、连续 ≥2 个、全部只读**才 `Promise.all`；写类工具永久串行；`run_command` 还得通过 `isReadOnlyCommand` 正则。
- 主 `for` 循环（`:1586`）依旧逐条 `await`，并发结果靠 `_poMap` 缓存旁路塞回去 —— 事件、超时、落盘逻辑仍然一条一条走。
- 没有依赖图，没有显式并行容器，多任务被绕成专用工具 `spawn_workers`（`tools.mjs:2144`）。

**C. 工具调用交付是「覆盖赋值 + 按轮去重」的一次性快照**

- `agent.mjs:1243` `toolCalls = takeFreshToolCalls(ev.toolCalls, sessionId, round)` 是**覆盖**；`takeFreshToolCalls`（`:196-218`）按 `(会话, 轮次)` 去重。
- 同一 round 里只要出现第二次 `tool_calls` 事件（断流续传、`[DONE]` 与 `finish_reason` 双触发），第二次返回空数组 → **把第一批冲掉 → 判定「说完了」→ 一个工具都不执行**。`agent.mjs:180-191` 的注释记过这次事故。
- `llm.mjs:614-618 / 658-660 / 682-686` 三处整批 yield + `acc.clear()`；XML 伪协议（`llm.mjs:673-677`）只在流收完且「一条正规 tool_calls 都没有」时解析一次，两条协议时机/id/增量能力完全不一致。

**D. 每轮全量重发历史，且就地改写活对象**

- `agent.mjs:1211-1223` 注释自承「第 N 圈发的是前 N-1 圈之和，prompt_tokens 在 1.4 万和 861 万之间跳」。
- `messages` 是会话里那个活数组，压缩/瘦身/量线提醒全就地 push + 自己清理（`:534-539`、`:1820-1833`）；前缀一变，prompt cache 全废。
- 每跑完一个工具做一次全量 `estimateTokens`（`:1736`）+ 五档量线循环（`:1759-1841`）+ 落盘。

**E. 「干什么都跑命令」**

- 工具其实有 `read_file / list_dir / search_files`，但提示词直到昨天才写「读文件用 read_file」；她习惯 `Get-Content` / `node -e` 遍历。
- `run_command` 在 Windows 上默认 `powershell.exe`（`tools.mjs` exec 参数），一次启动约 300ms；命令里再起一个 node 又 200ms。**命令还没干活就半秒没了**，且每条都要一整趟模型往返。
- 昨天已补 `search_files` 与 `timeout_ms`，但**默认 shell 没动**。

**F. 恢复策略散在三层、预算互相打架**

- `llm.mjs:483-542`（网关 2 次 / 溢出压一次 / 思考降档）、`agent.mjs:1205-1395`（断流 30 次 / 429 退避到 handoff）、`:1639-1659`（每工具独立 controller）、`deadline.mjs:77-92`（10/30/10 分钟）、`subagent.mjs:995-1034`（只 1 次、无 abort 传播）。
- 断流续传「带着半截话再要一次」没有幂等保护，可能重复执行写操作。

**G. 压缩把「模型行为」当成了存储层**

- `self-compress.mjs` 要求模型在正文里手写 `【压缩记忆·编号】`，程序用 `acceptSelfNote` 校验顾问腔/太短/没实字，再从正文捞出来落本子；同时 `SILENT_COMPRESS_RULE` 命令「一个字都不许说出口」。
- 正确性依赖「记得写 / 格式对 / 不说出口 / 写完继续干」四个行为约束，任一失守就是死循环（历史注释记过「压完又超线又压」）。

**H. 测试覆盖的空白**

- `scripts/` 下 45 个 `check-*`，绝大多数是读源码正则断言或 API 冒烟。
- **没有任何一条**测「一轮多个 tool_call 的执行顺序」「只读批是否真的并发」「覆盖赋值会不会丢批」「超时后是否正确回灌」「断流续传会不会重复执行工具」。

## 2. 如果是我来做：一句话的差别

> **我这边，模型只负责「想做什么」；要不要并行、能不能重试、该压多少、什么时候换路子，全是程序算的。**
> 她这边，这些判断**全压在模型身上**，而且提示词自己还在互相打架。

所以这次重做的总纲只有一条：

### 把判断从提示词挪进编排层

模型输出的是**意图**（调哪些工具、什么参数）；程序用**静态依赖图**决定执行顺序与并行，用**统一策略**决定重试/超时/压缩，用**指标**记录真实效果。提示词从此只保留「该用哪只手」的触发器，不再承担调度职责。

## 3. 目标架构

```
┌────────────────────────── 契约层（冻结，不许变） ──────────────────────────┐
│ SSE 事件 type/字段 · 会话落盘结构 · 工具名与参数 schema · 前端 DOM 依赖      │
│ 人设 / 底线 / 安全词 / 记忆本 / settings / outbox                          │
└───────────────────────────────────────────────────────────────────────────┘
                                    ▲
┌────────────────────────── 新建 src/harness/ ──────────────────────────────┐
│  tool-spec.mjs      工具依赖元数据（读集/写集/副作用/幂等性/快速通道）      │
│  tool-protocol.mjs  统一调用协议：原生 tool_calls 与 XML 收敛为增量事件流   │
│  scheduler.mjs      依赖图 → DAG 批次 → 并行执行 + 幂等键                  │
│  recovery.mjs       统一恢复策略：失败分类 / 重试预算 / 退避 / 总 deadline  │
│  context-budget.mjs 真实 usage 驱动的预算（只读，不往历史插消息）           │
│  telemetry.mjs      每轮指标：工具数 / 并行命中率 / 耗时分解 / 往返次数     │
└───────────────────────────────────────────────────────────────────────────┘
                                    ▲
┌────────────────────────── 接入层（最小侵入改写） ─────────────────────────┐
│  llm.mjs        → 增量 emit tool_call_done，不再三处整批 yield             │
│  agent.mjs      → Map 累积替代覆盖赋值；主循环改调 scheduler.executeBatch   │
│  persona.mjs    → 删掉自我否定条款；清单补「什么时候用」的触发器            │
│  tools.mjs      → run_command 快速通道：简单命令不进 PowerShell             │
└───────────────────────────────────────────────────────────────────────────┘
                                    ▲
┌────────────────────────── 验证层（新增） ─────────────────────────────────┐
│  check-harness-scheduler / -protocol / -recovery / -budget / -prompt       │
│  真机 DOM 探针 · 全套回归 · 生效同步                                        │
└───────────────────────────────────────────────────────────────────────────┘
```

### 五条不变量（任何一层都不得违反）

1. **契约不变**：SSE 事件、会话 JSON、工具名/参数、前端依赖的字段名，一个都不改。
2. **不丢工具**：任何情况下，模型发出的每个 tool_call 都必须有且只有一次 `tool_start`/`tool_end`。
3. **不乱并行**：有写操作或数据依赖的调用必须串行；宁可少并，不可跑出假结果。
4. **失败不静默**：超时/断流/失败必须有明确分类与回灌，绝不出现「日志没错误但她不动了」。
5. **可回滚**：每一阶段独立提交，任一阶段验证不过就回到上一个 tag。

## 4. 分层改造方案（逐层：现状 → 目标 → 做法 → 验收）

### L0　契约冻结
- **做法**：先跑一遍 `check-chat-events` / `check-ui` / `check-live-sync`，把当前事件表、会话结构存成基线快照（`docs/harness-baseline.json`）。
- **验收**：实施结束后同一套检查全过，且基线快照逐字段一致。

### L1　工具依赖元数据 `harness/tool-spec.mjs`（新建）
- **现状**：只读判定散在四处（`agent.mjs:124-143`、`agent.mjs:1543`、`task-mode.mjs:37-68`、`tools.mjs:2506`），彼此会漂移。
- **目标**：**单一真相**。每个工具声明 `reads / writes / sideEffect / idempotent / parallelSafe`。
- **做法**：表驱动，未登记的工具一律按「有副作用、串行」保守处理；导出 `canParallel(a,b)`、`dependencyEdges(calls)`、`isReadOnly(name,args)` 供全项目共用，四处旧判定改为调它。
- **验收**：`check-harness-spec` 覆盖「两个 read_file 可并行」「write_file 与任何调用不可并行」「run_command 只读命令可并行、带 `>`/`;` 的不可」「未知工具保守串行」。

### L2　统一调用协议 `harness/tool-protocol.mjs`（新建）
- **现状**：`llm.mjs` 三处整批 yield + `acc.clear()`；`agent.mjs:1243` 覆盖赋值 + 按轮去重；XML 兜底时机不一致。
- **目标**：**增量、幂等、累积**。每条 tool_call 完成即 emit 一次 `tool_call_done`（带 `index`/`id`/幂等键）；agent 侧用 `Map<id, call>` 累积，绝不覆盖。原生与 XML 走同一个 adapter。
- **做法**：
  - 新增 `createCallAccumulator()`：按 id 合并增量片段，重复 id 只保留内容更全的那份，**不去重丢弃**。
  - `toolCalls = takeFreshToolCalls(...)` 改成 `acc.merge(ev.toolCalls)`，同轮第二次交付变成「补充」而不是「冲掉」。
  - 保留 `takeFreshToolCalls` 导出（其它模块可能引用），但内部改为委托给 accumulator，行为从「丢重复」变「补全」。
  - XML 解析改成边流边扫 `<invoke …>` 成块即时 emit，不再等整条流收完。
- **验收**：`check-harness-protocol` 覆盖「同轮两次交付：第一次 3 个、第二次 2 个 → 合并后 5 个且都执行」「重复 id 幂等」「XML 与原生混发不丢」「标签切块」。

### L3　依赖图调度器 `harness/scheduler.mjs`（新建，替换窄补丁）
- **现状**：`agent.mjs:1526-1584` 只对连续 ≥2 只读并发，`run_command` 要过正则，写类永久串行，主 for 仍逐条 await。
- **目标**：按**依赖图**切 DAG 批次；无依赖的同批并行，有依赖的分层串行。模型发 1 个还是 5 个，程序都能正确处理。
- **做法**：
  - `plan(calls)` → 用 L1 元数据建边（写集与读集相交 = 依赖；写与写 = 依赖；显式顺序依赖保留原始 index 顺序）→ 拓扑分层。
  - `executeBatch(calls, { runTool, onEvent, signal })` → 逐层 `Promise.all`，层内每个调用独立 `tool_start`/`tool_end`、独立超时、独立失败回灌；层间严格等待。
  - **保留原有事件序列语义**：`tool_start` 在真正开始跑之前发，`tool_end` 在结果拿到之后发，字段不变。
  - 幂等键 = `sessionId + round + call.id`，同一键二次执行直接返回首次结果（防断流续传重复执行写操作）。
  - `agent.mjs` 里那段 `_poMap` 窄补丁整段删掉，主循环改调 scheduler；`_RO`/`_canPar`/`isReadOnlyCommand` 不再各自为政。
- **验收**：`check-harness-scheduler` 用假 `runTool`（记录时间戳）验证「3 个读并行且总耗时 ≈ 最慢那个」「读→写→读分三层」「某个失败不影响同层其它」「幂等键不重复执行」「事件成对」。

### L4　上下文预算 `harness/context-budget.mjs`（新建，只读化）
- **现状**：五档量线往 `messages` 里 push 提醒又自己清理；每跑完一个工具全量 `estimateTokens`；本地估算要靠真实 usage 校准（实测差 1.61 倍）。
- **目标**：预算成为**纯函数**，输入真实 `usage.prompt_tokens` + 当前预算，输出「要不要压、压多少」，**绝不往历史里插消息**。
- **做法**：新增 `assess(usage, budget)` 返回 `{level, ratio, shouldCompact, hint}`，UI 提示走 `onEvent` 而不走 messages。压缩触发仍由现有 `planTurnCompact` 决定，但量线提醒那条路改为调用它。
- **验收**：`check-harness-budget` 覆盖分档边界、单调性、无副作用（调用前后 messages 深度相等）。
- **范围控制**：**不动 `self-compress.mjs` 的模型手写摘要机制** —— 它跟人设强耦合，改了会动到「她怎么说话」。这一层只把它旁边的量线噪音清掉，并在计划里如实标为「保留」。

### L5　统一恢复策略 `harness/recovery.mjs`（新建）
- **现状**：断流 30 次 / 429 退避 / 网关 2 次 / 工具 30 分钟 / 整轮 180 分钟，散在三层；子 agent 不对等。
- **目标**：一张 `classify(error)` 表 + 一份预算；主循环与子 agent 共用。
- **做法**：
  - `classify(err)` → `retryable`（断流/5xx/429/静默看门狗）、`needsCompact`（上下文溢出）、`needsHandoff`（429 到阈值）、`fatal`（连不上/400/abort）。
  - `RecoveryPolicy` 统一退避 `min(2^n * 800ms, 8s)`、总预算、单类故障上限；把 `deadline.mjs` 的常量收进来做唯一来源。
  - **不改动现有续传/退避的调用点行为**（避免动到已经被主人验证过的「断流能接上」），只把散落的判断收敛到一张表，供后续统一。
- **验收**：`check-harness-recovery` 覆盖五类错误分类、退避封顶、预算耗尽后不再重试、abort 优先。

### L6　可观测性 `harness/telemetry.mjs`（新建）
- **目标**：以后不用靠翻会话文件猜「她为什么慢」。
- **做法**：每轮记录 `rounds / toolCount / parallelBatches / parallelHitRate / modelMs / toolMs / promptTokens / cachePrefixStable`，落 `.state/harness-metrics.jsonl`（追加、有上限），并在 `done` 事件里附一份摘要（新增字段是**追加**，不改旧字段，契约仍兼容）。
- **验收**：`check-harness-telemetry` 验证字段齐全、不阻塞主流程、文件有上限。

### L7　提示词契约 `persona.mjs`（重写工具段，人设/底线/安全词不动）
- **删**：`PARALLEL_TOOL_BLOCK` 最后一条「拿不准就一定一次一个」；`toolBlock` 里的「写文件和跑命令一次只做一件」「否则老实分开」；`PARALLEL_TOOL_BLOCK` 与 `toolBlock` 重复的两套并行说辞合并成一处。
- **改**：工具清单从「只给名字」变成「名字 + 一句什么时候用」的紧凑表（按 L1 元数据自动生成，不手写、不重复 description 全文）；明确写「**调度由程序负责，你只管把想做的事一次说全**」——把并行判断从模型身上卸下来。
- **留**：昨天加的「读文件用 read_file / 搜内容用 search_files / 失败两次换路子」三条，收紧措辞。
- **红线**：`PERSONA` / `BOTTOM_LINES` / `SAFE_WORD` / 人设卡 / 记忆本相关段落**一个字不动**。
- **验收**：`check-harness-prompt` 验证「不存在自我否定条款」「生成的提示词里每个工具都有触发器」「人设/底线/安全词与基线字节一致」。

### L8　`run_command` 快速通道 `tools.mjs`
- **现状**：Windows 上无条件 `shell: 'powershell.exe'`，每条命令 300ms 启动 + 常伴随再起一个 node。
- **目标**：**简单命令不进 PowerShell**。
- **做法**：新增 `pickShell(command)`：不含 PowerShell 专有语法（`$env:`、`Get-`、`|`、`Write-Output`、`$()` 等）且不含内建命令冲突时，用 `cmd.exe /d /s /c`；否则保持 PowerShell。参数追加 `shell_hint`（可选，默认 auto），**不删 `timeout_ms`**。命令里那套「中文路径 + 变量拼接」的烂写法由 L7 的规矩挡，不由这边兜。
- **验收**：`check-harness-shell` 验证分类正确、两条通道都能真跑通一条命令、超时说明仍在。
- **风险对冲**：默认仍保留 PowerShell 作为「拿不准就走老路」，只有明确安全的命令才走快路。

## 5. 明确不改的东西（红线）

| 项 | 理由 |
