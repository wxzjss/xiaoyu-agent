## 零、总原则

1. **实机验证优先**：任何"修好了"必须附带实机证据（截图 / 接口返回 / DOM 取值），只看代码不算。
2. **不改变运行时行为的重构优先于功能改造**：先清垃圾、拆结构，再动逻辑，最后加新功能。
3. **一件事一次提交**，提交信息写清"搬了什么 / 改了什么 / 验证了什么"。
4. **新人接手成本优先**：根目录 127 个下划线条目、19000 行单文件——这些不解决，下一个人（包括未来的我）还会改错文件白干一天。

## 一、主人本轮钦定（最高优先级，P0）

### 1.1 删除【办事模式】→ 新增【团队模式】

> **完整前后端设计另见 `docs/design-team-mode.md`**（后端 6 件事 + 前端三处呈现 + 接口契约 + 验收清单）
> 本节是摘要与决策依据，具体实现以设计文档为准。

#### 现状（已核实）
- 定义：`src/features.mjs:202` `id:'taskmode'`，`defaultOn:true`
- 实现：`src/task-mode.mjs`（573 行）+ 顶栏按钮 `public/index.html:3326`
- **核心机制（也是病根）**：`src/agent.mjs:159 toolsForTurn()` —— 办事模式开着时，用 `TASK_KEEP_TOOLS` 白名单把 `write_file` / `run_command` 等干活工具**从主智能体的 schema 里整个摘掉**，只留派活/清单/记事/翻史书。
  - 注释原话：「手里还攥着 write_file / run_command 的主智能体，一定会在某一次『我顺手改一下』里自己动起手来」
  - **这就是主人说的「只能等待或旁观」的根因**：不是她不想并行，是手被砍了，除了等 worker 没别的事可做
- 引用规模：代码层 21 个文件、874 处（含文档）

#### 目标（主人原话）
> 删除【办事模式】功能项，包括其按钮及描述文字；新增【团队模式】功能项并放入功能页。团队模式**不设按钮**，采用与你当前一致的交互行为：【主人】口头说明即可触发，系统也能自行判断是否需要拉起子 Agent 团队协同处理；子 Agent 执行任务期间，主 Agent 应能自主判断并**同时处理其他工作**，而不是只能等待或旁观。

#### 实施方案
**A. 删【办事模式】**
1. `src/features.mjs`：删 `taskmode` 功能定义整条（含 874 处引用里属于它的部分）
2. `public/index.html`：删顶栏 `<button id="taskBtn">`、珊瑚橙 `.on` 样式（138 行区）、`#taskBtn` 的点击/状态同步逻辑
3. `src/task-mode.mjs` 573 行：**这是关键判断** —— 里面除了"收走工具"，还有 worker 派活的实际实现（`spawn_worker` 等工具在 `src/tools.mjs:2145` 区）。**不能整文件删**，要拆：
   - 保留：worker 生命周期、进度档案、`watch_worker` 数据源 → 迁到 `src/team/worker-pool.mjs`
   - 删除：`taskOn()` 判定、`TASK_KEEP_TOOLS` 白名单、`toolsForTurn` 里的过滤分支、"你只派活别动手"那段提示词
4. 清理残留：`src/agent.mjs` / `agents.mjs` / `group.mjs` / `llm.mjs` / `persona.mjs` / `pick-helper.mjs` / `subagent.mjs` / `tools.mjs` / `harness/tool-spec.mjs` / `public/ui/chat.js` / `src-ui/items.js` / `src-ui/WorkerCard.jsx` 里的 taskmode 分支
5. 清理检查脚本：`check-feature-readpaths.mjs` / `check-features-portable.mjs` / `check-no-response.mjs` / `check-prompt-facts.mjs` 里 taskmode 相关断言（否则拆完必红）

**B. 新增【团队模式】**
1. `src/features.mjs` 新功能定义：
   - `id: 'team'`、`name: '团队模式'`
   - `tools: ['spawn_worker','spawn_workers','list_workers','tell_worker','watch_worker']`（**和智能体现有的 `ask_subagent` 分开**）
   - **`defaultOn: false`**（新功能默认关，符合 11-10 定的规矩：会主动开口/会改动界面的默认关）
   - `scope: 'session'`（按会话）
2. **不设按钮**：不加 header 按钮，只在功能页出现
3. **描述文字**（必须准确体现三件事，我起草）：
   > 开了之后我可以在干活的时候拉一支小队一起上：你说一句「帮我查三份资料」，我自己判断要不要拆、拆成几份、派给谁。派出去之后**我不停下来等**——它们跑它们的，我该干别的干别的，想起来就 `watch_worker` 看一眼进度、`tell_worker` 补一句。所有子智能体只属于这个会话，干完或会话删了就没了。这个开关**没有顶栏按钮**，全程我说了算；关掉之后我只会一个人干活。
4. **触发方式（两路，都要实现）**：
   - 路 1 · 主人一句话：功能开着 + 主人说「帮我…」（暗示多步/可并行）→ 提示词引导她自己决定是否拆
   - 路 2 · 系统判断：在 `agent.mjs` 给主智能体一段「什么时候该拉队」的判据（**不是硬编码规则，是提示词 + 现有工具**），避免为了"自动"写死启发式
5. **主 Agent 并行能力（核心，有两个根因，第二个是刚挖出来的）**

   **根因 1 · 工具被收走**：`toolsForTurn()` 把干活工具从 schema 里摘掉 → 手里没活可干，只能等。

   **根因 2 · `spawn_worker` 是同步阻塞的（更根本，我读代码确认）**：
   `src/tools.mjs:2151` 里面是 `r = await runSubagent({...})` —— **它会一直 await 到子智能体干完**。所以哪怕主智能体留着全部工具，只要调一次 `spawn_worker`，这一轮就卡在那儿了。
   `spawn_workers`（`:2196`）只是"多个 worker 之间并行"，**对主智能体仍然是整体 await**，而且它自己的描述还写着「等它们的时候可以先 watch_worker 看进度」——**这句话是假的，因为根本等不到那一刻，代码是阻塞的**。

   **所以【团队模式】必须新增"后台派发"能力**：
   - 新增参数 `background: true`（或新工具 `spawn_worker_bg`）：`spawn_worker` 立刻返回一个 `wid`，**不 await `runSubagent`**，把那个 Promise 挂到会话的 worker 池里自己跑
   - 主智能体拿到 `wid` 后立刻能继续干自己的活（这套机制基础设施已有一半：`noteWorkerProgress` / `drainWorkerMail` / `worker` SSE 事件都是现成的）
   - 干完之后怎么通知主智能体？两条路：
     - a) 下一轮系统提示里带上「你派出去的 #3 干完了，结果：…」（走现有的 peer mail / 待办注入机制）
     - b) 主智能体自己 `watch_worker` 轮询（非阻塞）
     - **两个都要有**：a 保证她不漏，b 保证她能主动看
   - **验证要点（实机）**：派 2 个后台 worker → 主智能体在同一轮里继续 `read_file` / `write_file`（有实际工具调用记录，不是嘴上说）→ worker 干完后下一轮她能说出结果

   **提示词也要改**：现在 `spawn_workers` 描述里那句「等它们的时候可以先 watch_worker」是**错的**，要改成「派出去立刻回来，你可以接着干别的，也可以随时 watch_worker 看进度」。

#### ⚠️⚠️ 1.1 的前置：`features.json` 是全表固化的，不迁移新功能永远不出现

**实测**（主人机器 `.state/features.json`）：
```
schemaVersion = 5，28 个键全是写死的，desktopHands: true 就在里面
```
**两个直接后果**：
1. 我早先把 `desktopHands` 的 `defaultOn` 改成 `false` —— **对已有安装完全无效**（读的是文件里那个 `true`）。`defaultOn` 只对「这个键从来没写过」的全新装机有效。
2. **新加的 `team` 功能如果只加一行定义 → 主人机器上永远不会生效**，因为文件里没有这个键，而 `resolveEnabled` 先查文件。

| # | 做什么 | 落在哪 |

| 1 | 启动（或首次 `readRaw`）时比对 `schemaVersion`，旧了就**只补缺的键**写回一次 | `src/features.mjs` 或新 `src/feature-migrate.mjs` |
| 2 | 已存在的键一律不动（迁移不能改主人的选择） | 同上 |
| 3 | `SCHEMA_VERSION` 从 5 → 6（本轮加 `team`） | `src/features.mjs` |
| 4 | 顺带加「坏文件自愈」：读不出来就 `rename` 成 `.bad-<时间戳>`，按出厂值重建 | 同上 |
| 5 | 加检查：造一个缺 `team` 键的旧 features.json，启动后必须自动补上 | `check-features-portable.mjs` |

**这个迁移不只服务 team** —— 以后每加一个功能都要它。没有它，功能页永远只显示第一版那 31 个。

### 1.2 【当前身份】权限收口：非主人身份只能用聊天相关功能

#### 现状（已核实，比预想的严重）
`isOwnerIdentity()` 全仓**只有 2 处真实调用**：
- `src/server.mjs:8902` —— 安全词判定
- `src/subagent.mjs:640` —— 子智能体的身份

**工具调用层完全没有身份校验。** 也就是说：切到「小鱼」或「小鲸」身份后，她依然能 `run_command`、`write_file`、看屏幕、操作桌面 —— 权限和主人一模一样。

#### 目标
除聊天相关功能外，**所有功能性工具/能力仅【主人】身份可触发与调用**。

#### 方案
**⚠️ 前置：先修 3 个会当场炸的隐患（tools-auditor 评估出来了，我核实过）**

| # | 隐患 | 证据 | 后果 |
|---|---|---|---|
| **P0-a** | **`setIdentity` 无条件写全局** `st.current = id` | `identity.mjs:288-297`，注释还写着「新会话默认继承它」 | 主人只是「试一下小鱼身份」→ **全机器所有会话都变非主人**：新开会话、定时任务、QQ 那头的人全按非主人处理。现在只影响提示词措辞，**一旦加权限闸 = 切一次身份全机器瘫痪** |
| **P0-b** | **闸只加执行层不改 schema** | `persona.mjs:613 toolBlock()` 从 `enabledToolSchemas` 现读，`:641` 写死「**这些工具你真能用**」 | 非主人身份的提示词里仍列着 `run_command` 还配「你真能用」→ 说了能做但做不到（重演 11-10 那个坑） |
| **P0-c** | **子智能体不继承身份** | `subagent.mjs:1141` 的工具清单只按功能开关过滤，不看身份 | 非主人身份一句「让小鲸去跑」→ worker 替她跑命令，闸等于没加 |

**修法**
1. **P0-a**：`setIdentity` 不再写全局 `current`（只有不传 sessionId 时才写）；`currentIdentityId` 的回退从「全局 current」改成「owner」→ 新会话默认主人
   - 代价：前端「新会话继承当前身份」的行为会变，要一起查（`identityState().current` 的用法）
   - **验收**：改完 cron / selfwake / qq 三条路各跑一遍，确认「没设过身份的会话 = 主人」
2. **P0-b**：**闸加在 `enabledToolSchemas(sessionId)` / `enabledToolNames(sessionId)` 这一层**（一个点同时管住 schema + `toolBlock` 清单 + 那句「你真能用」），`runToolInner` 再加一道兜底防硬编 tool_call
   - **这跟 11-10「按会话关工具」的正确做法完全同构**：schema 层收 + 执行层兜
3. **P0-c**：`runSubagent` 把 `IS_OWNER` 一路传下去，非主人身份派出的 worker 也拿不到 ownerOnly 工具
4. 顺带：`subagent.mjs:1141` 补 `gateSessionId`（见 2.2）

**ownerOnly 功能清单（我调整了 tools-auditor 的两条建议）**
- **仅主人**：跑命令、**写文件**、操作桌面、陪看屏幕、发文件、自动重启、定时任务、QQ 小鱼、做文档、画图、看视频、抓取成书、批量抓取、**智能体（ask_subagent）**
- **所有身份可用**：联网搜索、内置浏览器、长期记忆、技能本、便签、岁月史书、折叠箱、会话互递话、团队模式、小鱼说话、**读文件、看目录**（← 采纳 tools-auditor 建议：读一下不算越权，而且过了 `safePath` 只能读工作区。锁掉会让「小鱼身份」变成只会聊天的空壳，主人试一次就再也不用）
- **智能体必须仅主人**（或继承身份）：否则就是最大后门——非主人身份派活，worker 替她跑命令

**另一个必须处理的例外：cron / selfwake 轮次没有人在说话**
- `runCronTask`（`server.mjs:3001`）挑一个会话起轮次，**这一轮没有任何用户发言**
- 如果那个会话身份是「小鱼」→ `run_command` 全被拒 → 主人设的「明天九点备份文件」**静默失败**
- **判据**：这一轮没有人说话 = 视为主人（跟 `isOwnerIdentity` 现有「功能关了就永远是主人」同理），用 `turnSourceOf(sid)` + `_cron` 字段判断

**验收**：切到「小鱼」→ `run_command` 被拒（说人话）→ `web_search` 能用 → `read_file` 能用 → 派活给 worker（worker 也拿不到 ownerOnly 工具）→ 切回主人 → 全部恢复 → 定时任务照常跑

## 二、P0 硬伤（影响功能正确性，必须修）

### 2.00 🔴 深度闸门在并发下误拦 —— `spawn_workers` 现在就是坏的
**这不是新功能的问题，是当前版本就在丢功能。**

`subagent.mjs:463` 的闸门：
```js
if (subagentDepth() >= MAX_SUBAGENT_DEPTH) return { ok:false, text:'已经套到 2 层了…' };
```
而 `subagentDepth()`（`tools.mjs:340`）读的是**全局 `CTX.subagentDepth`**，不是 per-context。

**我实测**：
```
初始 depth = 0
A 起 depth = 1
B 起 depth = 2
C 想派活，闸门拦吗 = true (MAX=2)   ← 第三个必挂
```

**但情况比这更糟**：`bumpSubagentDepth()` 在 `subagent.mjs:488`，**比 `:1141` 的工具调用早得多**，所以：
1. `spawn_workers` 并发派 4 个（`Promise.all`）→ **第 3、4 个直接返回「已经套到 2 层了」**
2. 主智能体自己调 `spawn_worker` 时，**主轮的 depth 是 0**，第一个 worker 进去变成 1，第二个变 2 —— 看起来对
3. **但如果任何一个 worker 没走到 `finally` 的 `dropSubagentDepth()`（`:1199`）**（崩溃、abort、异常路径）→ depth 永久留在 >0 → **整台机器再也派不出 worker**，只能重启

**这就是为什么 `spawn_workers` 一直没人用** —— 它本来就跑不顺。

**修法**：`subagentDepth` 进 ALS（每个异步链路自己一份），或改成「按 sessionId + 父链」计数。**这是团队模式的前置条件之一**（见设计文档 1.1）。

### 2.0 ⚠️ 定时任务又坏了（新 P0，比下面所有都急）
**`startCron(...)` 整块被粘进了 `startSelfwake({ onDue: async (...) => { try {` 的函数体里**（`server.mjs:12061-12072`）。

后果：`startCron` 是模块级启动代码，**躲在回调里 → 模块加载时从不执行** → `cron.mjs` 的 `started` 永远 false → tick 永不起 → **一条定时任务都不会响**。

- 这是 `2eeceff` 那次提交粘错位置的（注释还写着「2026-11-10 修·定时任务从来没成功跑过」—— 修 `eol` 时把整块粘歪了）
- **实测**：`POST /api/cron {when:'+1m'}` → 过期 386 秒后 `lastRunAt=0, runCount=0`
- 手动 `POST /api/cron/run` **是好的** → 说明 `runCronTask` 没坏，坏的是调度器没启动
- **修法**：整段移到 `startSelfwake({...})` 的 try **外面**，跟它并列
- **必须加检查**：`check-cron-fires.mjs` 已有 12 条断言但**没抓到这个** —— 要加一条静态哨兵：`startCron(` 必须出现在 `startSelfwake(` 那个 try 的外面（**用括号深度算，别用正则**）

### 2.0b ⚠️ 点「停止」把她已经说出来的话整段抹掉（新 P0）
**现象**：她正写到 300+ 字，主人点 ⏹ → **那 300 多字当场消失**，磁盘上也一个字没有，刷新/重启都找不回来。

**实测 3 次中 2 次必现**：
```
[R2] 停止前 350 字 → 停止后 assN=0 len=0 | 磁盘 assistant 数=0  最长=0
[R3] 停止前 416 字 → 停止后 assN=0 len=0 | 磁盘 assistant 数=0  最长=0
```
磁盘会话文件只剩 `system` + 一条 `user`。

**三处叠加**
1. **服务端 abort 分支不 commit**：`server.mjs:10888-10890` 只 `send({type:'aborted'})`，**没有 `commitWireBack()` 没有 `saveSession()`** —— 对比正常收尾 `:10226` 那句 `commitWireBack()`，这条路跳过了
2. **前端只在 `onScreen()` 时收尾**：`index.html:8436-8440` → `endTurnQuietly()`（`:8357`）只做 close/flush，**不保留正文**

3. **先做 2.3（注入 `askApproval`）**，否则就算拦下来也只是「没动：主人没有点头」——**它没法点头，因为压根没弹窗**

### 2.6b 第二个症状：界面显示 `[object Object]`（同源，一次修掉）
**实测**：
```

```
**链路**：`clipToolResult`（`:2614`）`if (typeof out !== 'string') return r` 原样放过 → `agent.mjs:1884` 对象直接进事件 → `server.mjs:2254` / `src-ui/items.js:164,237` 的 `String(t.output || '')` → `[object Object]`

     const s = typeof r === 'string' ? r : (r && typeof r.text === 'string' ? r.text : '');

- **引用已删除的按钮（会让主人找不到）**：`tools.mjs:1251`/`:1749` 说「顶栏那颗小鲸按钮」—— **那颗 2026-11-02 就删了**（`index.html:211` 的注释原话：「她们的开关现在只剩左边『屋里的人』那两颗牌」），`index.html:10763` 的注释也还写着。要改成「左边『屋里的人』里把小鲸点上」

| ① 本轮刚开跑 | 3 ❌ | -1 | **-1** | -1 | -1 |
| ② 本轮一条 assistant | 5 | 5 | **5** | 5 | 5 |
| ③ 多轮工具后最终回复 | 7 | 5 ❌ | **7** | 7 | 7 |
| ④ 最终回复后又插话 | 7 | 5 ❌ | **7** | -1 ❌ | 7 |

```js
for (let q = messages.length - 1; q >= Math.max(0, turnStart); q--) {
  const m = messages[q];
  if (m && m.role === 'assistant' && !m.context) return q;
}
return -1;
```

**为什么其他三种不行**（都是实测，不是推测）：
- 只从末尾往前：① 本轮刚开跑时挂到上一轮
- 从 turnStart 往后找：③ 挂到本轮第一条 assistant（多半是 `tool_calls` 那条哑巴，文件挂在没话说的地方）
- 「最后一条 user 之后」：④ 主人中途插话时 `server.mjs:11528` 会 push 一条 `_steer` user，floor 被抬高，本轮最终回复被排除 → 返回 -1 → 回复被劈成两条

**⚠️ 注意**：`turnStart` 不能用裸下标 —— 虽然实测 `refreshSystem` 重建的是 `wire`（副本）不是 `session.messages`，但钉在语义上（消息对象）比钉下标稳。

### 8.2 危险词判断的「判据」—— 先有定义再写正则

`ui-guard.mjs` 一天内改了 4 种形态，每次都是「修一个误伤、引入一个漏拦」。根因是**没有一句话定义「什么叫危险」**。

判据（建议写进文件头）：
> **危险 = 这个操作会「不可逆地」改变主人东西的状态。**
> - 删文件 / 格式化磁盘 / 清空回收站 → 不可逆 → 拦
> - 点「Format Document」（VS Code 排版）→ 可逆（Ctrl+Z）→ 放
> - 打开回收站看看 → 不改变任何东西 → 放
> - 点「删除」弹出确认框 → 还没删，但下一步就删 → 拦
> - 帮助文档里的 Delete → 不执行 → 放

**同类对照**：`GLOBAL_ONLY_FEATURES` 有判据（「损失落在谁身上」），所以 6 条功能一次排好不用返工；`ui-guard` 没判据，所以改 4 次。
