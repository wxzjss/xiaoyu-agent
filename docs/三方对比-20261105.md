# 三方对比：DeepSeek Harness / WorkBuddy / 小鱼Agent

**2026-11-05**，基于三边的实际安装目录、配置和代码。

不是功能罗列，只看**"Agent 干活时到底怎么想、怎么做、怎么收尾"**。

---

## 一、定位差异（决定了后面所有设计）

| | DeepSeek Harness | WorkBuddy | 小鱼Agent |
|---|---|---|---|
| 形态 | Electron 桌面 + 云端模型 | 桌面 + CLI + 云端 | Electron 桌面 + 自带服务 |
| 定位 | **角色扮演优先**（QQ 里的鱼） | **干活优先**（工程/文档/数据） | 两者都想要 |
| 代码可改性 | 闭源，只能改 md 配置 | 闭源，只能写 skill | **全开源，能改服务端** |
| 上下文入口 | `AGENT.md` 全量注入 | 42 个 skill 的**描述**注入，正文按需 | 人设 + 记忆 + 工具描述全量注入 |

**关键差别**：dsh 和 workbuddy 都是"你只能用，不能改"，所以它们的设计被逼得很紧凑；小鱼Agent 能改，反而容易堆。

---

## 二、上下文组织（最值得看的一处）

| | 做法 | 每轮 token 量级 |
|---|---|---|
| **WorkBuddy** | 42 个 skill 只注入 `description`（合计 3349 字 ≈ 2.5k token），正文在 `references/` 里，**用到才读** | 小且稳定 |
| **DeepSeek Harness** | `AGENT.md` 4.7KB 全量塞进去 | 中，且不随场景变化 |
| **小鱼Agent** | 人设 965 字 + 记忆 ~1960 字 + 37 个工具描述 + 群聊/办事/规则块，合起来 system 已达 3292 字 | 中偏大，且**每轮固定** |

**WorkBuddy 那套叫「渐进式披露」**：主文件只回答"什么时候该用我"，细节铺在分册里。

看它的 skill 目录就明白：

```
skills/deep-thinking/
  SKILL.md          ← 只有 frontmatter（name/description/examples）+ 怎么用
  references/
    framing.md      ← 什么时候该重新框定问题
    evidence.md     ← 什么样的证据算数
    diagnosis.md
    ...
```

小鱼Agent 现在是反过来的：**所有东西都在主文件里**。

---

## 三、技能 / 工具的登记方式

| | 机制 | 加一个新能力要做什么 |
|---|---|---|
| WorkBuddy | 目录即插件：`skills/<name>/SKILL.md` + 可选 references | 建目录、写 frontmatter，**不用改任何代码** |
| dsh | 闭源插件市场 | 点安装 |
| 小鱼Agent | 硬编码在 `tools.mjs` 里 | 写实现 → 加进 tools 数组 → **登记到 features 白名单**（我今天就漏了这一步，导致 `memory_search` 永远是关的） |

**这是小鱼Agent 最该改的结构问题**：加能力要过四道关（声明/实现/登记/描述），漏一道就等于没做，而且**不会报错**。

---

## 四、记忆

| | 策略 |
|---|---|
| WorkBuddy | 三层：云端 profile（自动）/ 用户级 MEMORY.md / 工作区 memory。**工作区那份按目录隔离**，跨项目不串 |
| dsh | `.dsh/whale-loli.md` 57KB 单文件 + 一堆 `.bak`，人设和记忆混在一起 |
| 小鱼Agent | 固定区 + 80 条滚动 + 最近 5 轮详细；今天刚从"每轮注入 12000 字"改成"注入 22 条 + `memory_search` 自查" |

**dsh 那份 `.md` 已经 57KB 且有 4 个 `.bak`** —— 这是"全量塞一个文件"的必然下场。

小鱼Agent 现在走的正是 WorkBuddy 的路（索引 + 检索），方向对。

---

## 五、多 Agent

| | 模型 |
|---|---|
| WorkBuddy | **专家团**：一个 lead + 若干成员，一次性任务分工，lead 汇总。成员有独立人设/头像/职业 |
| dsh | 单角色为主（QQ 群里就一个鱼） |
| 小鱼Agent | **群聊**（几个角色长期共处）+ **办事模式**（主智能体派活给临时 worker，干完就散） |

小鱼Agent 的"办事模式"其实很像专家团——**但缺一个 lead 的汇总动作**。现在是 worker 干完把原文丢回来，主智能体要自己去核、去收。

---

## 六、错误处理与验证（差距最大的一块）

| | 出了错会怎样 |
|---|---|
| WorkBuddy | 工具返回结构化 `ok/error`；失败会明确说"没做成"，不给假的成功 |
| dsh | 闭源，看不到 |
| 小鱼Agent（今天之前） | **11 个工具失败还返回 `ok:true`**；`server.mjs` 有 284 个空 catch；命令跑挂了界面还是绿勾 |

今天修的：
- 统一 `ERROR：` 前缀 → `runTool` 判失败
- 命令退出码无条件上报
- 284 个空 catch 里挑关键的补了日志

**但"验证闭环"这个东西，三者里只有 WorkBuddy 是内建的**（我能跑 `check-ui`、能起真机、能读 DOM）。小鱼Agent 今天才补上（`_t_ui/_t_api/_t_tools/_t_write/_t_post/_t_agents2` 七套）。

---

## 七、人设表达（dsh 这一块最狠）

dsh 的 `AGENT.md` 有四段小鱼Agent 完全没写的东西：

```
说话铁律（活人感核心）
1. 短。 一次一两句，默认 1~15 字。
2. 像打字，不像写作文。 允许碎片、省略主语。
6. 不总结、不说教、不升华、不给免费人生建议。
9. 不客服腔。 不每条都关心人，不有求必应。

AI 味黑名单（出现即失败）
首先/其次/最后/综上所述/值得注意的是｜希望这个回答对你有帮助｜
作为 AI/作为一个语言模型/我无法｜这是个好问题/我理解你的感受｜
Markdown 标题、列表、加粗、引用块｜长篇大论解释｜
"保证""一绝""绝对有效""强烈推荐"
```

小鱼Agent 的人设 965 字，**0 处"不要/不许/别"**，也没有黑名单。

它现在是"我是谁"，缺"我不怎么说"。

## 八、值得借鉴的（按性价比排序）

| # | 借鉴什么 | 从哪来 | 成本 | 收益 |
|---|---|---|---|---|
| 1 | **AI 味黑名单** | dsh AGENT.md | 极低（加一段字） | 说话质量立刻变 |
| 2 | **渐进式披露**：人设/规则分册，主文件只留索引 | WorkBuddy skills | 中 | system 能瘦一半 |
| 3 | **技能目录化**：`skills/<name>/SKILL.md`，不用改代码 | WorkBuddy | 高（要动工具加载） | 加能力不再漏登记 |
| 4 | **lead 汇总**：办事模式里 worker 回来后强制主智能体先核再报 | WorkBuddy 专家团 | 低 | 少一次"她说完了但没交代" |
| 5 | **用量/成本可见** | dsh `.dshw-usage.json` | 低 | 知道钱花在哪 |

**不借鉴的**：
- dsh 的"1~15 字短句"——那是 QQ 场景，桌面端要说清技术细节，照搬会废
- dsh 的"单文件 57KB 人设"——已经证明会烂

---

## 九、小鱼Agent 真正该改的三处（按痛感）

1. **加能力要过四道关且漏了不报错** → 改成目录化（借鉴 #3），或者至少加一道启动自检："features 里登记的工具名，必须在 tools 里存在；反之亦然"
2. **system 每轮 3292 字且固定** → 分册（借鉴 #2）
3. **人设只有"我是谁"，没有"我不怎么说"** → 黑名单（借鉴 #1）

第 1 条最值得做——**它今天已经咬过一次**（`memory_search` 白装）。

## 十、落地记录（2026-11-05 晚）

| 改动 | 效果 |
|---|---|
| **工具描述不再抄第二遍** | system 里的工具清单从「名字 + 120 字描述」改成「只列名字」。API 的 `tools` 字段本来就带完整描述。**省 4645 字／轮 ≈ 1452 token** |
| **AI 味黑名单** | 补上「我不怎么说」那一半（客套/助手腔/免责腔/捧场腔/假承诺/收尾升华） |
| **工具登记自检** | 启动时检查「有实现但没登记到 features」的工具——这类工具会被静默关闭（今天 `memory_search` 就这么白装过） |
| **system 预算闸** | `_t_prompt.mjs` 每次自检量一遍，超 5000 字就报错。当前 4552 |

### system 4552 字的真实构成（`_t_prompt.mjs` 量出来的）

```
【重启只能走这一条路】+人设+编码标签   1291  28.4%
【你手上有什么】(工具名 + 硬提示)      1011  22.2%
【上下文太长的时候…】                   485  10.7%
【说话规矩】                            477  10.5%
【别说这些】                            247   5.4%
【主人说这几个词】                      234   5.1%
【改完先自己验】                        224   4.9%
开头 / 人设正文                         198   4.3%
其他（思考语言 / 群聊 / 人设档）         387   8.5%
```

**下一步能砍的**：人设里那批编码标签（`CETACEA_LOLI` / `MODE_TAIL_FLUKES` / `LANG_ZH_CN_ONLY` …）
一行一个、信息密度极低，占了人设的大半。但那是主人自己写的人设，**没动**。
