# 技能本：往 data/skills 里丢文件，她就会做新事

**2026-11-05 加**。不用改代码、不用改人设。

---

## 一、怎么加

建一个目录，放一份 `SKILL.md`：

```
<数据目录>\skills\weekly-report\SKILL.md
```

数据目录通常是：
- 免安装版：`exe 旁边的 data\`
- 安装版：`%APPDATA%\小鱼Agent\data\`

目录名用**英文/数字/横线**（`weekly-report`、`video-cut`），中文名容易在某些路径处理上出岔子。
真正的显示名写在 frontmatter 里。

## 二、文件长什么样

```markdown
---
name: 写周报
description: 把一段时间做过的事整理成周报，分「做完了／在做／卡住／下周」，给数据不给空话
when: 主人说「写周报」「整理这周」「这周干了啥」
---

# 写周报

## 先收集，再写
1. 先翻会话记录和记忆本……
2. 拿不准的别猜……

## 结构
...
```

**三个字段**：

| 字段 | 必须 | 作用 |
|---|---|---|
| `name` | ✅ | 她看到的技能名（可以中文） |
| `description` | ✅ | **一行说清"这手艺干什么用"**。缺了它，她只看到一个名字，不知道该不该翻 |
| `when` | 可选 | 什么情况下该用（写不写都行，写了更准） |

正文随便写：步骤、格式、例子、禁忌都行。

## 三、她是怎么用到它的

**渐进式披露**（跟 WorkBuddy 的 skill 一个路子）：

1. 平时 system 里只有**索引**——一行一条，名字 + 描述，几十字；
2. 要做那件事时，她自己调 `use_skill` 把正文读进上下文；
3. 读完再动手。

所以：
- **加十个技能也不会撑爆 system**（只多十行字）；
- 但**描述写得含糊，她就不会翻**——这是唯一的门槛。

## 四、改完什么时候生效

技能目录带 **1.5 秒缓存**。改完等一下，或者重启一次。

## 五、删掉

删目录就行。没有注册表、没有索引文件要清。

## 六、自检会管什么

启动时检查（`[skills]` 开头的日志）：

- 目录名不合法（有中文/空格/特殊符号）
- 缺 `SKILL.md`
- frontmatter 缺 `name` 或 `description`
- 正文是空的

**只警告、不拦启动**——某一份坏了不影响别的。

## 七、现在有什么

| 目录 | 名字 | 干什么 |
|---|---|---|
| `coding-discipline` | 改代码的规矩 | 先想再写、只碰必须碰的、别顺手"优化"旁边的东西 |
| `debug-first` | 改坏了怎么查 | 先复现、再定位、一次只改一处；禁止东试西试 |
| `before-claiming-done` | 说"做完了"之前 | 四问：真跑过吗、推活了吗、半途了吗、拿声明当证明了吗 |
| `align-before-start` | 开工前先对齐 | 要解决哪个问题、怎么算做完、有没有更简单的路 |
| `weekly-report` | 写周报 | 四段结构、给数字、不写空话 |

**前四个是 2026-11-05 从 WorkBuddy 的 42 个 skill 里挑出来重写的**，
分别对应她最容易犯的四类毛病（不暴露假设就动手 / 出问题瞎试 / 说做完了其实没验 / 没对齐就开干）。

照它们的格式改一份就能加新的。

### 加技能时的两条经验

1. **`name` 用中文，而且要自解释。** "说'做完了'之前" 比 "delivery-check" 好 ——
   她扫一眼索引就能判断该不该翻。
2. **`description` 写「什么时候用」，不写「这是什么」。** 索引里只有一行，
   这一行决定她翻不翻。
