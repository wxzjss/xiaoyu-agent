每条都带**可核对的行号**，按「用户能感觉到的严重程度」排序，不按代码优雅度。

## 一、消息显示

### 1.1 每个 token 都把整条消息的 textContent 整体重写　`✅ 已重做`

- **证据**：`index.html:5504` `bubble._rawText += text` 之后整条走 `paintSpeech(bubble, _rawText)`；`5494` 对每个段落 `el.textContent = paras[i]`
- **后果**：流式生成时**无法选中复制**——每来一个字，选区就没了。长回复越后面越明显。
- **修法**：改成只在末尾追加一个 TextNode。`adoptThink`（`8669`）里已有正确写法可抄：`t.indexOf(_cur) === 0` 就 append 尾巴。
- **成本**：中

### 1.2 每 1.2 秒把正在流式的整条消息删掉重建　`✅ 已修（快路增量）`

- **证据**：`paintSnapshot`（`5266`）开头 `document.querySelectorAll('.msg.assistant[data-live-turn="1"]').forEach(c => c.remove())`；轮询间隔 `6709` 处 `1200`
- **后果**：思考块和工具卡都做了「认领复用」，唯独正文气泡是 remove 重建 → 整块抖动、`Ctrl+F` 跳走、节点高度突变时滚动跳一下。`5294` 的注释自己承认这块被 remove 掉了。
- **修法**：照 `adoptThink` / `adoptTool` 的模式给 `.msg.assistant` 做 id 认领。
- **成本**：中

### 1.3 流式把段内单换行压平，历史路径却保留　`✅ 已修`

- **证据**：`5455 flat()` 把段内 `\n` 删成空 → `paras = cleaned.split(/\n[ \t]*\n+/)`；历史路径 `17195` / `17220` 直接 `textContent = fixMojibake(turn.text)`
- **后果**：生成时代码/缩进/ASCII 图被压成一行，跑完或 F5 后突然变回多行。
- **修法**：`flat` 只压 `\n{3,}`，保留单换行；"中文句中软断行"用更窄的规则单独处理。
- **成本**：小-中

### 1.4 不认 markdown，且主动剥记号　`✅ 已修（保守版）`

- **证据**：`5520 stripMarkdownMarks` —— ` ``` ` 围栏整行删、`\`x\`` 只留内容、`#{1,6}` 删、`**x**` 只留字；`4819` 注释："气泡里是纯文本（textContent），不认 markdown"
- **后果**：表格塌成一堆竖线；代码块无围栏无高亮；标题层级消失；URL 是纯文本、点不了。
- **修法（已做，保守版）**：新增 `mdInto()`，**只在正文确实带 markdown 特征时**才变身富文本；没特征就走原来的 `textContent`，普通聊天观感零变化。
  - 只处理：代码块（带等宽、横向滚动、单独复制按钮）、表格（转 `<table>` + 横向滚动）、标题、无序/有序列表、`**粗体**`、`` `行内代码` ``、裸链接可点。
  - 安全：全程 `createElement` / `textContent` 构建，不拼 `innerHTML`，她说的内容里带标签也只是文字。
  - 判据实测：12 个样本（含「5 - 3 = 2」「她走了 —— 没回头」这类易误判的）全部符合预期，见 `_t_md.mjs`。
- **遗留（要知道）**：只在**历史渲染**这条路生效。流式过程中仍是纯文本（每收一个 token 就整篇重新解析 markdown 太贵，半截代码块也会画得乱七八糟），所以「生成时朴素、刷新后变好看」——和 1.3 是同一类不一致，建议跟 1.2 的重构一起解决。

### 1.5 长消息没有折叠　`✅ 已修`

- **证据**：`.bubble`（`287/291/322/329`）全部没有 `max-height`；`src/folded.mjs` 是"上下文压缩存档"，跟 UI 无关
- **后果**：两千字全铺屏，一屏看不见第二条。
- **修法**：`max-height` + 渐变遮罩 + 展开按钮；注意会改变 `#log` 滚动高度，要跟 `resetScrollStick` 一起测。
- **成本**：小（但要连带回归滚动）

### 1.6 用户发的图片只剩 26×26，且点不开　`✅ 已修`

- **证据**：`713` `.attachChip .thumb { width:26px; height:26px }`；`7270` 发消息时同样用 `.thumb`；全文件无 lightbox
- **后果**：发截图问"这个按钮在哪"，永远只有 26 像素小方块。
- **实际做法**：消息里的图 128×128；点开 `#imgView` 看原图（关闭键固定在视口右上角，点图外空白、Esc 都能关）。
  - 图**不再显示文件名**（主人说"碍眼"）：名字进 `img.title`，悬停能看到。
  - 文件（pdf/zip）仍挂名字 —— 那里名字是唯一能说明"这是什么"的信息。
  - JS 层直接不创建名字节点，不只靠 CSS `:has()` 隐藏（老版 Electron 不认 `:has()`，那是兜底）。

### 1.7 没有消息时间戳

- 全文件没有渲染消息时间的 DOM。属于设计取舍，如果不需要可忽略。

## 二、UI 交互

### 2.1 往上翻历史会被拽回底部　`✅ 已修`

- **证据**：`renderTurns` 收尾调 `resetScrollStick()`（`4050`，内含 `stickBottom = true` + 同步滚底 + rAF 再滚一次）；补历史监听 `17345` 先 `renderTurns` 再同步还原 `scrollTop`，但 rAF 那一发又把 `stickBottom` 贴回去；叠加 `4311` 每 250ms 的 `followNow`

### 2.6 工具卡没有耗时、没有进度　`✅ 已修`

### 3.4 tool_calls 参数被瘦身成非法 JSON　`✅ 已修`

### 3.5 压缩复用上一份摘要（段号形同虚设）　`✅ 已修`

- **证据**：`self-compress.mjs:138 lastSelfNote()` 只取"最近一条"note；`compress.mjs:1027` 直接拿它当摘要。而 `compress.mjs:980` 的段号是 `'seg-' + sessionId + '-' + Date.now()` —— **每次调用现生成**，dryPlan 给工作单时一个号、真压时又一个号，永远对不上。
- **后果**：第一次压缩之后，以后每次涨到 80% 都拿**上一段**的摘要替换**这一段**的原文，四道闸门全过。
- **为什么没改**：按段号严格比对会**永远不匹配**（时间戳每次都变），一改就把压缩彻底堵死。正确做法是先把 `segId` 改成**稳定指纹**——由"要折的那一段"的首尾消息位置 + 内容哈希算出来，保证 dryPlan 与真压两次调用得到同一个值；然后才谈得上校验。
- **建议**：
  1. `segId = 'seg-' + sid + '-' + start + '-' + end + '-' + sha1(第一条内容).slice(0,8)`
  2. `lastSelfNote(sid, { wantSegId })` 只返回匹配的那条
  3. 不匹配时返回空 → 自然走"重新递工作单"的分支
- **成本**：中（改 3 个文件，但逻辑清晰；风险在于 segId 变更会影响已有会话里存的旧 note，需要一次兼容处理）

### 3.6 记忆归档同月覆盖，原件已删　`✅ 已修`

### 3.7 tool_calls 交付条件太窄，会静默丢调用　`✅ 已修`

## 四、修复进度

**第十轮｜不好改的两条，重做了**

**1.1 流式渲染：从"每个字重写全文"改成"只动最后一段"**

原来每来一个 token 都走 `paintSpeech`：全文跑一遍正则，再把**每一段**的 textContent
重写一遍。长回复七八段，等于每个字都把前面没变的段也重写 —— 浏览器跟着重排，
选区跟着断（这是"流式时复制不了"的另一半原因）。

重做方式：`pushStreamText` 里加一条快路，条件很严 ——
段落数没变 + 前面每一段一个字都没动 + 只有最后一段在长。
满足就只更新最后那一段的文本，**别的节点一个都不碰**；不满足原样走 `paintSpeech`。
顺手把 `flat` 提取成模块级的 `flatSpeechText`，让两条路用同一套换行规则（不然必然走样）。

真机 5 条断言：逐字推进不重建节点、第一段内容正确、换段时新建第二段、
换段后第一段节点不变、第二段推进不重建。全过。

**3.8 超时掐不断子进程：从"传错东西"改成"每个工具一个 controller"**

原来把**整轮的 signal** 当 `ac` 传给 `withTimeout`，可 `AbortSignal` 没有 `.abort()` ——
deadline 里那句 `ac?.abort('timeout')` 必然抛 TypeError，又被空 catch 吃掉。
所以注释里写的"认输后顺手把底层连接掐掉"从来没生效过：30 分钟到点，agent 往下走了，
子进程还活着，继续占 CPU、继续改工作区。

现在每个工具一个自己的 `AbortController`：
- 主人点停止 → 同步掐这个工具；
- 本工具超时 → 只掐它自己，不影响别的工具和下一轮；
- 两者用 `AbortSignal.any` 合起来交给工具。
`runTool` 顺带加了第 4 个参数（借 `runWithToolContext` 覆盖信号，不碰全局 CTX，并发不串）。

实测：
```
超时判定 = true
controller 被掐 = true      ← 以前这里是 false
命令被掐掉 = true            → [主人点了停止，命令被掐掉]
```

**3.12 的两套瘦身：重新判断，不动**

上一轮我把它列进"待办"，这轮看清楚了：`compact-core.slimHistory` 改的是**历史本身**
（省磁盘、省后续 token），`turn-slim.slimRoundMessages` 改的是**发出去的那份副本**
（保证 JSON 合法、不污染落盘）。两层各管一件事，合并反而会错。

所以它不是"不好改"，是**不该改**。真要收拾，只能把两者的裁剪规则对齐（`slimArgsKeepingJson`
已经让 compact-core 也保证了 JSON 合法），这已经做了。



**第九轮｜3.3 收口：用约定代替逐个修补**

16 处"失败却返回一句话"的地方，没有一个个改成 `{ok:false}` —— 那样得动 16 个 return，
其中还有跨行拼接的，改一处错一处。改成**统一约定**：

- 工具用 `ERROR：` 开头表示"这件事没办成"；
- `runTool` 见到这个前缀就判 `ok:false`（界面变红、模型收到 ERROR 前缀）；
- 以后新加工具，写 `ERROR：` 就自动算失败，不用再记着改包装层。

覆盖：`restart_self` 找不到重启入口、`ask_peer` 递不出去、`t2s_convert` 缺库/没东西可转、
`folded_list`/`folded_read` 不知道哪个会话、`spawn_worker(s)` 不是办事模式或任务为空、
`tell_worker` 没给 key 或没递进去、`watch_worker` 没有这个 worker、`plan`/`note` 拿不到会话 id。

**边界划清了**：「空结果」不算失败 —— `list_workers` 没有 worker、`folded_list` 没折过东西、
`memory_search` 搜不到，这些都是"查了，确实没有"，仍然 `ok:true`。测试 `_t_toolfail.mjs` 两头都钉住了。

**顺手抓到自己的一个疏漏**

`memory_search` 加进 `tools.mjs` 之后**没登记到 `features.mjs` 的开关表**。
那张表是白名单 —— 没写进去，工具就是"关着"的状态，她会看到「现在是关着的，用不了」，
等于把刚给她装的眼睛又捂回去。

补上之后实测：写入一条 → 搜「备份 穿越」→ 滚动区和详细区都命中。
这也说明一件事：**新工具要过的关不止一道**（声明 + 实现 + 登记 + 描述），漏一道就等于没做。



**第八轮｜把她变轻（3.11 / 3.12）**

**3.11 记忆：从"每轮背一遍"改成"要用时翻得到"**

原来每轮固定注入 12000 字（80 条滚动 + 固定区 + 详细区），跟这轮聊什么无关。
现在：

| | 之前 | 现在 |
|---|---|---|
| 注入滚动条数 | 80 条 | **22 条**（`INJECT_ROLL`） |
| 注入字数（实测 80 条时） | 上限 12000 | **约 1960** |
| 早期记忆怎么找 | 背在提示里 | 新增 `memory_search` 工具自己查 |

- `memory_search(query, limit)`：关键词空格分开，命中几个词算几分，同样命中偏爱新的那条。不分词、不算相似度——记忆本是短句，这样够用且可预测。
- 注入区的标题会明写「这里只给最近 22 条，共 N 条 —— 更早的用 memory_search 查」，她知道自己缺了什么、也知道去哪找。
- 实测：80 条本子里搜「备份 目录穿越」「段号 时间戳」都能命中，不存在的词返回 0，固定记忆也能搜到。

净效果：**每轮省下约 10k token**，这些额度现在能装真正的对话历史。

**3.12 token 估算：两套口径合成一套**

带图会话里，闸门（`compact-core.estTokens`）把图片乘了校准系数、真压（`compress.estimateTokens`）没乘，
于是闸门算出的比例高约 1.6 倍 —— 一边喊「到 80% 该折了」，一边算出来才 50%，
`compressHistory` 返回 `under-trigger`，**每轮都判定该压、每轮都压不动**。

现在图片在两边都不乘（那个系数是拿文字字符/token 反校的，套 base64 会带偏）。
实测同一份带图+带工具调用的历史：**两套口径差异 0.00%**（32321 vs 32321），
回归脚本 `_t_est_parity.mjs` 会一直盯着这件事。

**第七轮｜1.2 / 1.3 真的修了**

不重构原逻辑，改用**入口拦截 + 收紧条件**的办法：

`tryLiveAppendFast(sid, live)` 放在 `paintSnapshot` 最前面，四条全满足才走快路：
1. 这一轮还在跑（`running === true`）；
2. 快照里**只有 `k:'text'`**（一出现工具/思考/子任务立刻交回老路 —— 那些卡必须重画）；

**1.2 用真机定性了**

实测（`_t_ui.mjs` 的流式断言 + 单独探针）：
- 流式推 6 段，容器节点**稳定**（1.1 的"相同值跳过"有效）
- 但一调 `paintSnapshot`，`isConnected` 立刻变 false —— **节点确实被删重建**

为什么仍然不改：绘制路径（`k === 'text'` 分支）每次都是 `addAssistantAuto()` → `addAssistant()` → `addEl()`，**无条件新建**。要复用就得改 `addAssistant` 的语义，而它同时服务正常流式和快照重画两条路 —— 改错的后果是「两条气泡各写一半」。
判断：收益（少一次重排、选中不被打断）小于风险，且"不能复制"已由复制按钮解决。
