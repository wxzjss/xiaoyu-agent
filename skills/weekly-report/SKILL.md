# 写周报

## 先收集，再写
1. 先翻会话记录和记忆本，把这段时间**真做过**的事捞出来（`memory_search` 能搜关键词）。
2. 拿不准的别猜：翻不到就说"这条我记不清了"，不要编一条像样的。

## 结构（固定四段，顺序别换）

**做完了**
- 一件事一行，写「做了什么 + 结果是什么」。
- 有数字就写数字：改了几个文件、修了几个 bug、跑了多久、省了多少 token。
- 有文件就带上路径，主人能直接点开。

**在做**
- 写到哪一步了，下一步做什么。
- 卡在谁身上（等主人决定 / 等外部接口 / 等数据）要说清楚。

**卡住**
- 只写真的挡路的。不挡路的小问题放"在做"里。
- 每条写：卡在哪 + 需要什么才能解开。

**下周**
- 最多三条。写"做什么"，不写"继续推进"这种废话。

## 不要这样写
- 不写"完成了相关工作""持续优化"——没有信息量。
- 不总结意义，不写"本周收获良多"。
- 不为了凑字数把一件事拆成三条。
- 没有的事不要编。

## 长度
- 一般 10~20 行。事情少就写短，别硬撑。
